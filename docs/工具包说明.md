# SDDP 工具包说明（`utils/`）

与问题解耦：`utils/` **不 import `code/`**。问题侧只提供一个模块顶层工厂，`utils`
整目录拷到别的项目即可复用。

```python
from utils import SDDPEngine, Cut, trivial_cut, simulate

eng = SDDPEngine(prob, make_sub, solver_cfg, results_dir=None, log=print)
eng.train(200)                       # 轮数/前向路径/后向场景都从 solver_cfg 读
st = simulate(eng, n_paths=10000, chunk_size=1000)
```

工厂契约（必须是**模块顶层函数**，spawn 按引用 pickle）：

```python
make_sub(t, prob, cfg) -> 子问题对象     # 只建 base，不含割
```

子问题对象需具备：

| 方法 | 作用 |
|------|------|
| `assemble(cuts_next, key=None)` | 拼装未来成本割；`key` 与上次相同则跳过 |
| `set_state(x)` | 锁状态（改变量界）|
| `set_scene(scene)` | 改场景相关行右端（须在 `set_state` 之后）|
| `set_point(x, scene)` | = 上两步 |
| `solve_mip()` / `solve_lp()` | 整数求解 / LP 松弛求解 |
| `obj` / `stage_cost()` / `out_state_vector()` / `gradient()` | 取值与对偶 |
| `free()` | 释放底层模型 |

`prob` 需有 `.pool`（等概率场景序列）、`.state_dim`、`.T`、`.initial_state()`。

## 各模块

### `cut.py` — 割的表示与存储

```python
@dataclass
class Cut:
    alpha: float        # 截距；割形如 V(x) ≥ alpha + beta @ x
    beta:  np.ndarray   # 次梯度 ∂Q/∂x，与状态向量同序同维
    state: np.ndarray   # 生成该割的 backward 试验点（留痕：复现/剪枝/策略分析）
    stage: int          # 割近似的值函数期号
    obj:   float        # Q(state)，逐场景期望目标值
    it:    int          # 创建该割的训练轮次（0 = 平凡割）
```

- `value_at(s)` 给出割在 s 处的下界；`pack(cuts, dim)` → `(alpha, beta)` 稠密数组。
- `alpha = obj − beta @ state`，与点式 `θ ≥ obj + β·(x − x̄)` 代数等价；取截距式是因为
  子问题的割约束直接写成 `theta >= alpha + Σ beta_j·xout_j`。
- 磁盘格式 `cuts.json`：`{meta, version, cuts: {"1": [cut_dict, ...], ...}}`，
  原子写（`.tmp` → `os.replace`），几百 MB 也不会毁掉上一份。
- `meta` 里带 `n_iterations`，续训据此定起始轮次。

### `copt_env.py` — coptpy 环境与落盘兜底

`new_model(cfg)`（按配置设 `Threads`/容差/关日志）、`solve(m, mip=)`（返回目标值，
失败即抛）、`check_optimal`、`values` / `redcosts`、`dump_lp`（**先写 ASCII 临时目录
再搬回** —— COPT 的文件接口不认中文路径）、`close_model`。

三条实测约束写死在这里，别处不要绕开：中文路径落盘、失败时 `objval` 是陈旧值、
`objval` 对 LP 值有粘性。详见 `COPT使用手册.md` §0 与 §7.2。

### `payload.py` — 割集跨进程传递

一阶段一块 `shared_memory`（`put_cuts` / `attached`）。主管程每阶段写一次，任务只带
块名；worker 在任务内映射、任务结束即关。按任务 pickle 的话每轮 IPC 量是割表本身的
进程数倍（实测规模下达 20 GB/轮）。shm 不可用时回退为任务内直接 pickle。

**粒度是一阶段一块而不是一轮一块**：后向只用到 `cuts[t+1]`，一轮一块会在每次换阶段时
重写整张表，总量退化成 O(T²)。

`attached` 对空割集返回 `None` —— 调用方必须把 `None` 与"空割集"区分开：空割集会让
theta 进目标却无约束，LP 无界。

### `worker.py` — spawn worker 装配与任务函数

worker 全局状态由 `init_worker` 装配一次。**每 worker 只持 2 个模型**：

- `stage0`：虚拟首阶段，结构特殊，常驻；
- `shared`：服务所有 `t = 1..T`。阶段 1..T 的 base 结构完全相同（约束与目标系数全
  静态），唯一差异是挂载的割集 ⇒ 一个模型 + 按阶段换割行即可。

换割行的键是 `(round_id, t, pass_tag)`：键不变就跳过（同一阶段内所有场景/试探点复用
同一个模型，只改变量界与行右端）。内存从最坏 (T+1) 个模型降到 2 个。

三个任务函数：

| 任务 | 粒度 | 返回 |
|------|------|------|
| `forward_path_task` | **一条路径**（t=0..T 完整走完）| `(states, costs, total, records)` |
| `backward_point_task` | **一个试态点 = 一条割** | `(beta, obj)`；`alpha` 由主管程算 |
| `lower_bound_task` | 阶段 0 解 LP | `float` |

### `engine.py` — SDDP 引擎

- **阶段 0..T**：阶段 0 是虚拟首阶段（钉初值 + 决定首期订货），1..T 为真实周期。
  `cuts[t]` 近似 V_t，第 t−1 期子问题用 `cuts[t]` 约束其未来成本变量 theta。
- **前向**：`forward(n_paths)` 一任务一路径，一次 `map`；返回 `(trial, results)`，
  `trial[t]` 是该阶段的全部试态点。
- **后向**：`backward(trial, it)` **按阶段串行（t = T..1），期内按试态点并行**。每个
  阶段：本阶段全部试态点的割算完，一起入池，再推进到 t−1 —— 这样期 t−1 用到的
  `cuts[t]` 已含本轮新割。**这是修好"下界长期为 0"的关键**：旧实现轮初打割快照、
  全部 (期 × 试态点) 一次铺满，期 t 用不上同轮期 t+1 的新割，信息每轮最多传播一期。
- **场景抽样**：全在**主进程**用 `engine.rng` 抽（路径与后向场景子集都是），保证与
  进程数无关、可复现。`n_backward_samples = 0` 表示全枚举。
- **多进程**：`multiprocessing` + spawn，`n_processes=1` 退化为串行、traceback 完整。
- **失败兜底**：子问题求解失败时 `dump_lp` 导出现场 LP（经 ASCII 临时目录），抛
  `SolverError` 带期号与场景号，供 `AnalysisModel_IIS.py` 分析冲突集。
- **回调**：`eng.on_iter = fn(rec)` 逐轮回调（run.py 用它落 CSV）。
- **割筛选（LML1）**：`cfg.cut_selection == "lml1"` 时，每期在生成完本轮割后调
  `_lml1_update`。它维护「每期历史试探点 → 该点处最大的、生成最早的割」，
  没被任何点选中的割从 `cuts[t]` 里删除（保留 `it == 0` 的平凡割以保证 theta 有下界）。
  `cut_select_keep_rounds > 0` 时只保留最近若干轮的试探点，`|S|` 才有硬上界。
  **删除是安全的**：割集是值函数的下包络，删几条只会让近似变松（下界仍合法），不会失效。

### `simulation.py` — 蒙特卡洛

分块仿真（块内即弃，几万条也不顶内存），块种子 = `seed + k`，因此**结果依赖
chunk_size**（只影响随机流切分，不影响统计量口径）。`SimStats` 流式累加总成本与逐期
成本，给出均值/标准差/标准误/95% CI/最小最大。逐期累加的是**真实单期成本**（不含
theta）。仿真沿用引擎的前向任务，故口径与训练前向完全一致。

### `diagnostics.py` — 对偶自检

拿到 β 之后必须做的三件事，改模型/冒烟后用：

| 函数 | 验什么 | 判据 |
|------|--------|------|
| `dual_crosscheck` | `.dj` vs 通用式 `c_s + Σ_c a_c·π_c` | 相对误差 ≤ 1e-6 |
| `subgradient_inequality` | β_j 是合法次梯度 | 左右单侧差商夹住 β_j |
| `cut_validity` | 割全局合法 | 探测点上 `α + β·s ≤ Q(s)` |

**为什么不用中心差分判真伪**：折点处中心差分给的是左右斜率均值，它本身就是一个合法
次梯度，无法判假；次梯度不等式才是充分必要判据。差分步长用 `DIFF_H = 1e-4`
（1e-6 会被求解器容差放大成 100% 误差）。

### `io.py` — 结果目录与落盘

结果目录建/配置**原样拷贝**（`write_configs`）/一致性校验（`problem_diff` 比对决定
模型结构的字段，不一致就拦下 resume）/割与 JSON 原子写/`TrainingLog`（空格分隔，表头
与 SDDP.jl 一致，`plot/plot_bounds.py` 可直接解析）/日志归档/summary。

## 踩坑记录（本项目实测）

1. **COPT 文件接口不认中文路径**：`writeLp/writeMps/writeBin/writeSol/writeIIS/
   setLogFile` 遇非 ASCII 路径失败，**短路径还会静默不建文件**（比报错更危险）。
   本项目路径全中文 → 落盘一律先写 `tempfile.gettempdir()` 再搬回。
2. **失败时 `objval` 是陈旧值**：不可行/失败后 `m.objval` 与 `Attr.LpObjVal` 都
   静默返回**上一次**的值，只有 `m.status` 可靠。每次求解后必须查。
3. **`objval` 对 LP 值有粘性**：同一模型上跑过 `solveLP()` 后，`objval` 永远返回 LP
   值，即使 `solve()` 已给出整数解（`getValues()` 是对的，`objval` 对不上，且
   `Status` 照样报 OPTIMAL 判不出来）。⇒ MIP 读 `BestObj`、LP 读 `LpObjVal`。
4. **`Threads` 默认 -1 = 自动用满核**：多进程下必须设 1（实测 3000 变量 LP 单线程
   0.020 s vs 自动 0.040 s）。并行度留给进程级。
5. **`m.getRow(con)` 是副本语义**：有 `setConstant/setCoeff` 但改完重解不生效。
   改行右端走 `setInfo(Info.LB/UB, [con], v)`，改矩阵系数走 `m.setCoeff(con, var, v)`。
6. **`remove()` 不会让其它行句柄失效**：实测删 A 后改 B、C 的右端仍精确生效 ⇒ base
   里的静态行句柄可以一直复用，换割集只需 remove 旧割行 + addConstr 新割行。
7. **空割集必须等同"无割"**：收到空 `(alpha, beta)` 要把 theta 钉在 0，否则 theta 进
   目标却没有任何割行约束它 ⇒ LP 无界。
8. **`setInfo` 的容器分派**：`tupledict + list` 会 `TypeError`（被当成单值走
   `float()`），而 `addVars` 返回的正是 tupledict。要么 `list(d.values())` 要么传标量。
9. **`resetParam()` 不带参数**（一次复位全部参数）；`setParam` 返回 `None`，不能拿
   返回值判成败。
10. **`loadMatrix` 灌进来的变量/约束没有名字**，`getVarByName` 取不到，只能按位置索引。
11. **批量 `LinExpr.addTerms(vars, coeffs)` 比逐项构造快 5 倍**（实测 2000 条 × 615
    非零：1186 ms → 223 ms），大割集下这是主成本，别改回逐项 `quicksum`。
12. **COPT 容差默认**：`FeasTol/DualTol/IntTol = 1e-6`、`MatrixTol = 1e-10`、
    `RelGap = 1e-4`/`AbsGap = 1e-6`。实测 FeasTol 边界：冲突量 ≤1e-6 判可行、>1e-6
    判不可行；`(1−θ)~1e-5` 的系数远在 MatrixTol 安全区内。
13. **模型可行性对状态有硬耦合**：随机生成的探测状态几乎必然不可行（本模型要求
    `Σ_a n_in[r,a] ≤ N_r + Σ_a F`），探测点要按约束构造（用多项分布切分 N_r）。
14. **Windows 控制台是 GBK**：`print` 里放组合符号（如 `z̄` 的 U+0304）会抛
    `UnicodeEncodeError`；入口脚本统一 `sys.stdout.reconfigure(errors="replace")`。
15. **Julia → Python 的 `enumerate` 差一**：本项目的 `tc_route = (pos−1)·tc` 在
    Python 里必须写 `enumerate(..., start=1)`，否则本地调拨成本变成 −tc。
16. **多进程 + 中文路径**：Git Bash 下把中文路径放进 shell 变量会被编码搞坏，整条命令
    用引号包住绝对路径，或直接用文件工具。
17. **Windows spawn 必须加 `if __name__ == "__main__":` 守卫**：建进程池的脚本没有
    守卫，子进程重新 import 主模块时会再建一次池，无限递归。
18. **不要用 `os.dup2` 去压 COPT 的许可横幅**：曾经在 spawn worker 里把 fd 1 指向
    devnull 想吞掉横幅，结果**当 stdout 是控制台时会让 worker 假死**（`cp.Envr()` 永久
    阻塞 → worker 拿不到任务 → 主进程在 `pool.map` 上无限等，0% CPU）。二分实测：只
    `import coptpy` 正常、`import` + `cp.Envr()` 正常、**先 dup2 再建 Envr 挂死**。
    重定向到文件跑则无此问题 —— 只在终端里直接跑才踩得到。已移除该 hack。

19. **`multiprocessing.Pool.map` 不保证任务→worker 的固定映射**：配合共享常驻模型与
    自动热启动，会让"取到哪个最优对偶"（对偶退化下多解）随调度变化 ⇒ 数值路径不逐位
    复现。不影响正确性，详见项目 CLAUDE.md「已知边界」一节。
