# SDDP 工具包说明（`utils/`）

与问题解耦：`utils/` **不 import `code/`**，问题侧只提供两个东西 —— 一个子问题构造
回调和一个状态维度/初值。整目录拷到别的项目即可复用。

```python
from utils import SDDPEngine, Cut, trivial_cut, make_solver, simulate

eng = SDDPEngine(prob, build_stage, T=..., state_dim=..., initial_state=...,
                 n_processes=None, seed=0, results_dir=None)
eng.train(200, n_forward_paths=1, n_backward_samples=None)
st = simulate(eng, n_paths=10000, chunk_size=1000)
```

回调契约：

```python
build_stage(t, state_vec, scene, cuts_next, prob, it) -> 子问题对象
```

子问题对象需具备：`solve(solver)`、`obj`、`stage_cost()`、`out_state_vector()`、
`gradient(method) -> np.ndarray`、`decision_values() -> dict`。
`prob` 需有 `.pool`（等概率场景序列）。

## 各模块

### `cut.py` — 割的表示与存储

```python
@dataclass
class Cut:
    alpha: float        # 截距；割形如 V(x) ≥ alpha + beta @ x
    beta:  np.ndarray   # 次梯度 ∂Q/∂x，与状态向量同序同维
    state: np.ndarray   # 生成该割的 backward 试验点（留痕：复现/剪枝/策略分析）
    stage: int          # 割近似的值函数期号
    obj:   float        # Q(state)，逐场景期望目标值
    it:    int          # 创建该割的训练轮次（0 = 平凡割）
```

- `value_at(s)` 给出割在 s 处的下界；`pack(cuts, dim)` → `(alpha, beta)` 稠密数组，
  跨进程只传这份。
- `alpha = obj − beta @ state`，与点式 `θ ≥ obj + β·(x − x̄)` 代数等价；取截距式是因为
  子问题的割约束直接写成 `theta >= alpha + Σ beta_j·xout_j`。
- 磁盘格式 `cuts.json`：`{meta, version, cuts: {"1": [cut_dict, ...], ...}}`，
  原子写（`.tmp` → `os.replace`），几百 MB 也不会毁掉上一份。

### `training.py` — SDDP 引擎

- **阶段 0..T**：阶段 0 是虚拟首阶段（钉初值 + 决定首期订货），1..T 为真实周期。
  `cuts[t]` 近似 V_t，第 t−1 期子问题用 `cuts[t]` 约束其未来成本变量 theta。
- **每轮**：前向 pass（并行采样路径解 MIP）→ 后向 pass（对每个试态点枚举场景解 LP
  松弛取 `.dj`，场景平均得期望次梯度 → 一条割）→ 下界（阶段 0 子问题，`mip=False`）。
- **多进程**：`multiprocessing` + spawn，worker 由 `_init_worker` 装配一次并持有
  问题数据与场景池，任务里只带**场景下标**，割按 `pack` 后的稠密数组传。因此
  `build_stage` 必须是**模块顶层函数**（spawn 按引用 pickle）。`n_processes=1`
  退化为串行、traceback 完整，便于调试。
- **确定性**：串行与并行结果逐位一致（同一 `seed`、同一场景路径序列）。
- **失败兜底**：子问题求解失败时把现场 `writeLP` 导出到结果目录，抛 `SolverError`
  带期号与场景号，供 `AnalysisModel_IIS.py` 分析冲突集。
- **回调**：`eng.on_iter = fn(rec)` 逐轮回调（run.py 用它落 CSV）。

### `simulation.py` — 蒙特卡洛

分块仿真（块内即弃，几万条也不顶内存），块种子 = `seed + k`，因此**结果依赖
chunk_size**（只影响随机流切分，不影响统计量口径）。`SimStats` 流式累加
总成本与逐期成本，给出均值/标准差/标准误/95% CI/最小最大。逐期累加的是
**真实单期成本**（不含 theta）。

### `diagnostics.py` — 对偶自检

拿到 β 之后必须做的三件事，冒烟/改模型后用：

| 函数 | 验什么 | 判据 |
|------|--------|------|
| `dual_crosscheck` | `.dj` vs 通用式 `c_s + Σ_c a_c·π_c` | 相对误差 ≤ 1e-6 |
| `subgradient_inequality` | β_j 是合法次梯度 | 左右单侧差商夹住 β_j |
| `cut_validity` | 割全局合法 | 探测点上 `α + β·s ≤ Q(s)` |

**为什么不用中心差分判真伪**：折点处中心差分给的是左右斜率均值，它本身就是一个合法
次梯度，无法判假；次梯度不等式才是充分必要判据。差分步长用 `DIFF_H = 1e-4`
（1e-6 会被求解器容差放大成 100% 误差）。

### `io.py` / `solver.py`

- `io.py`：结果目录、config 读写、割/JSON 原子写、`TrainingLog`（空格分隔，表头与
  SDDP.jl 一致，`plot/plot_bounds.py` 可直接解析）、日志归档、summary。
- `solver.py`：`make_solver(mip=..., use_copt=True)` → COPT_DLL 优先、CBC 兜底；
  MIP 下 COPT_DLL 拒绝返回对偶（安全），CBC 返回的是 LP 松弛对偶（危险）——
  所以取对偶的求解一律显式 `mip=False`。`export_lp` 供 IIS 用。

## 踩坑记录（本项目实测）

1. **pulp 常量目标返回 None**：目标里没有任何变量时（虚拟首阶段无割）`pulp.value`
   返回 `None`，不能直接 `float()`。`obj` 属性须退回 `objective.constant`。
2. **预求解会消掉"只被界钉住"的变量**：虚拟首阶段的 `xout`（除 q 槽外）不进任何
   约束，求解器不回值 → `out_state_vector()` 对这些分量要退回已知的界值。
3. **`pulp.LpProblem` 的目标是覆盖语义**：`prob += expr` 只能写一次，多处加项要先
   合成一个表达式（本项目统一走 `_finish()`）。
4. **变量名不要与函数参数重名**：诊断函数里把容差变量命名成 `t` 会覆盖期号 `t`，
   第二次循环起就在求解**别的期**的子问题，症状是差商突变成天文数字。
5. **模型可行性对状态有硬耦合**：随机生成的探测状态几乎必然不可行（如本模型要求
   `Σ_a n_in[r,a] ≤ N_r + Σ_a F`），探测点要按约束构造（如用多项分布切分 N_r）。
6. **Windows 控制台是 GBK**：`print` 里放组合符号（如 `z̄` 的 U+0304）会抛
   `UnicodeEncodeError`；入口脚本统一 `sys.stdout.reconfigure(errors="replace")`。
7. **Julia → Python 的 `enumerate` 差一**：Julia 从 1 开始，Python 从 0 开始。
   本项目的 `tc_route = (pos−1)·tc` 在 Python 里必须写 `enumerate(..., start=1)`，
   否则本地调拨成本变成 −tc（负成本会把整个 LP 解带跑偏）。
8. **多进程 + 中文路径**：Git Bash 下把中文路径放进 shell 变量会被编码搞坏，
   整条命令用引号包住绝对路径，或直接用文件工具。
9. **失败兜底要先建目录**：`_fail` 里 `export_lp` 之前要 `mkdir(parents=True)`，
   否则目录不存在时异常被吞、`path` 静默变成 `None` —— 最需要现场 LP 的时候反而
   没导出。
10. **COPT 许可横幅只能从 fd 层压掉**：`[ Warn] Your COPT license expires in N
    days` 由 COPT 原生库在**进程卸载 DLL 时**（DllMain detach，晚于所有 Python
   代码包括 atexit）向 fd 1 打印，**每个 CreateEnv 打一条**，Python 的
   `redirect_stdout` 拦不住，copt_cfg/环境变量也没有开关。实测有效的做法
   （`utils/solver.py::_silence_copt_banner`）：spawn 出的 worker（daemon）把
   fd 1 永久指向 devnull（worker 的合法输出只有异常，走 fd 2）；主进程在
   atexit 里**先 flush 自己的 stdout** 再把 fd 1 指走 —— 自己的输出一行不丢，
   COPT 退出时的 N 条横幅全进 devnull。
