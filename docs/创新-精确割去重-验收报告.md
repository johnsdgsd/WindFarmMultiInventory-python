# 算法验收报告：精确 beta 割去重（小幅正收益）

## 0. 结论

**通过“合法性/精确性”验收，但收益偏小，未达到明显改善门禁。**

- 完全相同 `beta` 的割只保留 `alpha` 最大的一条；对任意状态 x，`max(alpha+beta x)`
  不变，根 LB 逐位不变。
- T60 保存割 25,673 行 → 24,051 个唯一 beta（**−6.3%**）；终端阶段
  1,281 → 525（**−59%**）；T240 总体 143,912 → 133,747（−7.1%），
  终端 3,771 → 145（−96%）。
- T60 同 3061.7 s + 2000 路径：146 轮，LB **714.2689**，UB **822.7277**，
  gap **13.1828%**；基线 128 轮，LB 712.9522，UB 825.4215，gap 13.6257%。
- 配对 2000 路径：UB 差 **−2.6938 ± 1.8323（95% CI）**，t=−2.88；
  LB **+1.3167**；gap **−0.4428 pp**。
- 这是精确、无风险的割压缩/提速，但 0.44 pp 不足以称为“明显改善”。

## 1. 实现

- `utils/payload._dedup_exact`：按 `beta.tobytes()` 精确分组，保留最大 alpha；
- `put_cuts(..., dedup=True)` 只压缩跨进程载荷，**不改规范 cuts 池**、不删 Cut、
  不改 `FORMAT_VERSION`；
- `SolverConfig.dedup_cuts` 与 `max_train_seconds`；`config/dedup/` 为处理组；
- `test/_t_dedup.py` 验证根 LB 不变；`_t_config.py` 50/50 通过。

## 2. 结果

| 轮次 | 128 | **146** |

| LB | 712.9522 | **714.2689** |
| UB（2000） | 825.4215 | **822.7277** |

| 约束审计 | 全部通过 | 全部通过 |

## 3. 判断

- 去重是**正确且可复现**的精确优化，但 T60 的行数节省只有 6.3%，主要收益集中在
  终端阶段；同时间多跑了 18 轮，只换来 +1.32 LB / −0.44 pp。
- 早前的高段回放 period=5 结果 gap 13.08%，仍优于去重组；去重更适合作为
  **T240 的提速使能**（终端 −96%），或与其它割生成方案组合。
- 下一步：在不改变 SDDP 主循环的前提下，继续试状态采样/割生成；若仍无明确收益，
  再评估更激进的聚类条件割/多割表示。
